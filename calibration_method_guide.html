机器人三相机在线标定
方法、数学原理与实施流程

适用于 两个固定第三视角相机（Cam1 / Cam2）+ 一个随 EEF 运动的 Wrist Camera。先标定三台 RGB 相机内参，再计算 Wrist-to-EEF 手眼外参，最后在不同重叠区域分别求解 Cam1、Cam2 到 Robot Base 的外参，并将 EEF 位置与旋转轴投影回三个相机画面，直观检验标定。

01 · Coordinate conventions

统一坐标系与变换方向

全工程统一使用 TA←B 表示“将 B 坐标系中的点变换到 A 坐标系”，即 p_A = T_A_B @ p_B。这是理解全部计算公式的前提。

符号含义来源 / 属性
BRobot Base统一目标坐标系
G机器人末端刚性坐标系（flange / tool0）由机器人 FK 获得；必须固定定义
WWrist Camera optical frame随 EEF 运动
C1、C2两个第三视角相机 optical frame相对 Robot Base 固定
PChArUco 标定板坐标系Stage 1 固定；Stage 2 可组间移动
TB←GEEF → Base机器人 FK
TW←P、TC←P标定板 → 相机ChArUco + PnP
统一约定：平移一律用米（m），相机 3D 坐标使用 OpenCV optical frame：X 向右、Y 向下、Z 向前。需要明确 ROS camera_link 与 camera_optical_frame 的区别；FK 不可混用 flange 与 TCP。
02 · Stage 0 — Intrinsic calibration

三台相机分别标定 RGB 内参

内参决定三维点如何投影到图像。Wrist / Cam1 / Cam2 分别独立标定，此阶段只需要相机图像，不需要机器人 FK。

针孔模型与畸变

K = ⎡ fx　0　cx ⎤
　　⎢ 0　fy　cy ⎥
　　⎣ 0　0　 1　⎦普通针孔模型；像素坐标由透视投影 + 畸变模型得到。

使用 Brown–Conrady 五系数模型 D = [k1, k2, p1, p2, k3]（径向 + 切向畸变）。

采用 ChArUco 的原因

结合棋盘格角点定位精度和 ArUco 编码 ID，在部分可见条件下依然能够建立带物理尺度的 3D–2D 点对应关系。

示例标定板

8 × 6 方格

格长 35 mm

Marker 25 mm

成品 280 × 210 mm

须按实际尺寸打印并测量

采集方法

选择一台相机，开启原始 RGB 预览

固定分辨率、焦距/对焦状态、裁剪方式；程序单独接入该相机。

从不同位置、倾角和距离采集 25–40 张图像

每张建议至少检测到 12 个 ChArUco 角点，覆盖画面中央、边缘和四角；加入约 ±20°–45° 倾角。

求解 K / D 并检查逐帧重投影误差

使用角点 3D–2D 对应调用 cv2.calibrateCameraExtended()；剔除部分异常帧。

保存内参并用于后续 PnP

分别生成 configs/wrist_intrinsics.yaml、cam1_intrinsics.yaml 和 cam2_intrinsics.yaml。

Stage 0 · 采集与求解 
# 三台相机分别采集（GUI：c 采集、q 退出）
python -m multicalib intrinsics capture --camera wrist
python -m multicalib intrinsics capture --camera cam1

# 全部完成后一次求解内参
python -m multicalib intrinsics solve --camera all

python -m multicalib intrinsics solve --camera wrist
重要：内参对应的必须是后续 PnP 所使用的同一图像模式。若图像经过缩放、裁剪或去畸变，需同步调整 K / D，不能把 raw RGB 的 D 再作用到 rectified 图像上。RGB-D 的 Depth 内参及 RGB–Depth 对齐不包含在这个 Stage 0 中。
03 · Stage 1 — Eye-in-Hand

Wrist Camera 与 EEF 的手眼标定

本阶段通过 EEF 的 FK 轨迹，以及 Wrist 观测固定标定板所恢复的相机相对运动，估计固定的 EEF ← Wrist 刚体变换。

机器人提供

EEF 轨迹

每个采样姿态的 TB←G(i)，来自真实机器人关节角和 FK / ROS2 TF。

TB←G(1), TB←G(2), …必须包含多轴旋转，而不是只做 XYZ 平移。
视觉提供

标定板观测轨迹

每个 Wrist 图像利用已知内参、ChArUco 角点和 solvePnP 得到 TW←P(i)。

TW←P(1), TW←P(2), …整个 Stage 1 中，标定板必须严格固定。

核心数学原理：AX = XB

A · X = X · BA 和 B 分别是 EEF、Wrist 的相对运动；X = TG←W 是要求的固定手眼外参。
Aij = (TB←G(i))−1 · TB←G(j)
Bij = TW←P(i) · (TW←P(j))−1

代码使用 OpenCV calibrateHandEye()（Park / Tsai 初值），随后联合优化手眼外参和固定标定板位姿，使不同采样反算出的标定板姿态尽可能一致。

TB←P = TB←G(i) · TG←W · TW←P(i)因为标定板在 Stage 1 中固定，所以右侧所有有效姿态 i 的计算结果应一致。

04 · Stage 2 — Camera-to-Base

分别将 Cam1、Cam2 标定到 Robot Base

你的部署方案重点在于：先把 Wrist 标定好，再主动调整 EEF 位姿，让 Wrist 分别与 Cam1、Cam2 有更大的共同视野。两个固定相机彼此之间不需要有视野重叠。

每一组配对样本，使用同一块可见标定板

Stage 2A 和 Stage 2B 使用同一计算公式；每次都利用当前 FK 更新 Wrist 相机在 Base 下的位姿。
TB←Cᵢ(k) = TB←G(k) · TG←W · TW←P(k) · (TCᵢ←P(k))−1i ∈ {1,2} 表示目标第三视角相机，k 表示一次配对采集；最终从多组 k 估计一个固定 TB←Cᵢ。

为什么 Stage 2 能移动标定板？

公式中两台相机同时观测到的是当前这次采集对应的同一个标定板坐标系 P(k)。两次采集之间，板可以移到其他位置，Wrist 也可以重新调整；因为两个 PnP 都在本次配对中重新估计，板的全局位姿会在公式中消去。

Stage 2A · Cam1

Wrist 移至 Cam1 共同视野

使 Wrist 和 Cam1 都能清晰拍到标定板。每组采集 Wrist RGB、Cam1 RGB、EEF FK；组间可以改变板姿态与 Wrist 视角。

Cam1 
python -m multicalib capture --stage cam1
python -m multicalib solve --stage cam1
Stage 2B · Cam2

Wrist 移至 Cam2 共同视野

重新移动 Wrist 到 Cam2 方便标定的位置，与 Cam1 标定无关；重复相同的配对采集与求解过程。

Cam2 
python -m multicalib capture --stage cam2
python -m multicalib solve --stage cam2
每组必须静止：机器人和标定板在一组双图像与 FK 采集期间都要保持静止。只有这一组采集完成后，才能移动标定板；否则两个 PnP 不再对应同一个标定板位姿。

一组图像够不够？

采集策略每台第三视角相机适合什么场景
单组快速求解1 组：Wrist + Cam + FK数学上可估计 6DoF 外参，但不能独立评估可靠性
推荐正式标定8–12 组不同板位置 / 朝向鲁棒融合、异常值剔除、留出样本检查
更严格验证额外独立采集 3–5 组检查未用于求解的位姿误差
05 · Online workflow

在线操作：从准备到保存的完整步骤

准备设备

检查三个相机能持续输出原始 RGB；安装打印尺寸准确的 ChArUco 板；确认 EEF FK、时间戳与坐标系定义。

分别完成 Stage 0（wrist / cam1 / cam2）

为每个相机收集多个倾角和画面位置的图像，生成三个内参 YAML。完成后锁定相机图像模式。

Stage 1：固定板，采集 Wrist + FK

手动安全移动 EEF 至多组不同旋转姿态；通过 GUI 的 c 键逐组保存。最后按 s 求解或调用命令行 solve。

Stage 2A：调整 Wrist 位置 → Cam1 配对

每组拍摄同一块静止板，双图像均通过 PnP 且机器人静止。组间可移动板与 Wrist。

Stage 2B：重新调整 Wrist → Cam2 配对

针对 Cam2 重复阶段 2A，不需要 Cam1 与 Cam2 看到相同区域。

验证并加载到机器人系统

查看输出报告、留出误差、三相机 3D 点在 Base 下的一致性；最终用保存的矩阵转换 RGB-D 点云或 3D Action。

在线 GUI 操作约定

按键作用适用
c保存当前有效图像 / 配对样本Stage 0 / 1 / 2
s在采集界面直接求解并保存Stage 1 / 2
q / Esc退出当前采集窗口所有采集阶段

外参采集界面可查看 ChArUco 角点数、PnP 重投影 RMS、图像新鲜度与采样数量。数据不满足有效性或静止条件时会拒绝本次采集。

08 · Stage 3 — Reprojection validation

把 EEF Position + Rotation 投影到三路 RGB 图像验证

这是完整标定的最后一步：读取三台相机内参 K/D、Wrist 手眼外参、Cam1/Cam2 到 Base 外参和当前 EEF FK，将同一个 EEF/TCP 的三维位置以及局部 X/Y/Z 坐标轴投影到每台相机的原始 RGB 画面。可直接观察标定的坐标方向、偏移及运动响应。

三个画面中的 XYZ 朝向可能完全不同，这是不同相机成像方位造成的；但它们对应的是 同一个 Base 中的 EEF 位姿。

数学关系：统一 Base → 每个相机 optical frame → 像素

从机器人实时 FK 获得 TB←G(t)，其中 G 必须与 Stage 1 中用的 flange/tool0 完全一致。首先计算每台相机的 Base 外参：

TB←W(t) = TB←G(t) · TG←W
TB←C1 = fixed from Stage 2A   ·   TB←C2 = fixed from Stage 2B

然后得到 EEF 相对于各相机的位姿：

TCᵢ←G(t) = [TB←Cᵢ(t)]−1 · TB←G(t)Cᵢ ∈ {W, C1, C2}；特别地，TW←G = (TG←W)−1，由于 Wrist 与 EEF 刚性连接，这个变换不会随机器人运动改变。

选择一个位于 EEF 坐标系 G 下的投影原点 p_G。若要投影实际 TCP，须使用已知的 p_G = t_G_TCP；否则默认为 EEF 原点。为了可视化 Rotation，构造局部 X/Y/Z 三个长度为 L 的轴端点：

pGX=pG+[L,0,0]T,  pGY=pG+[0,L,0]T,  pGZ=pG+[0,0,L]T
pCᵢ = RCᵢ←G · pG + tCᵢ←G  →  (u,v) = π(Ki,Di,pCᵢ)π 使用 OpenCV cv2.projectPoints，原始 RGB 图像必须配合原始 K/D；对于去畸变/rectified 画面应改用对应的新 K 和 D=0。
Position

投影黄色原点

将当前 EEF/TCP 的 XYZ 三维位置变成图像像素 (u,v)。检查圆点是否落在真实夹爪目标物理位置。

Rotation

投影 XYZ 轴

红 X、绿 Y、蓝 Z 的方向反映 EEF 的旋转。结合实际夹爪朝向与已知几何特征判断是否发生轴反转或错帧。

Multi-View

对三路画面验证

同一个 FK 位置与旋转在 Cam1、Cam2 中应分别对应真实末端位置；Wrist 画面中 EEF 相对位姿保持不变。

output/T_base_cam1.npy、T_base_cam2.npy固定相机外参两个相机物理位置不变
当前 T_base_gripper + 三路图像当下 EEF 6DoF 投影机器人静止时检查；图像与 FK 为同一姿态
尤其重要：EEF 原点可能完全不可见。 flange / tool0 常位于夹爪内部或 Wrist Camera 后方，因此即使所有标定都正确，默认黄色点也可能在画面外。请将 --origin-offset-m 设置为真实 TCP 在 G 下的三维偏移，或用 --points-json 指定实测的夹爪特征点。投影的 XYZ 轴默认与 G 平行；如果需要呈现有旋转偏移的 TCP 轴，应额外使用完整 TG←TCP 进行轴方向变换，不能只改 XYZ 偏移。
如何判断成功：在 Cam1 和 Cam2 的不同机器人静止姿态下，投影点应持续落在真实末端的对应可见特征上，三轴方向随实际机械臂姿态变化正确；Wrist 中相对几何保持固定。由于只有投影轴并没有人工标注真实 2D 关键点，这只是可视化一致性检查，不能直接证明毫米级外参精度。若要定量评估，需要人工/自动标注真实可见 TCP 或已知特征点，比较像素误差，并进一步做独立三维测量。
09 · Validation & troubleshooting

如何判断标定是否可靠

完成 Stage 3 的可视化后，还需要客观误差评估。最终评估不应只看一个重投影 RMS。对机器人精密操作，必须分别检查 像素级拟合、多姿态几何一致性 与 实际三维点云在 Base 下的对齐。

验证层次检查内容用途与解释
Stage 0全局 / 逐帧重投影 RMSE，K / D 合理性，角点覆盖分布发现内参退化、错分辨率、模糊图
Stage 1多姿态反算 TB←P 的平移与旋转一致性检验 FK / 手眼 / PnP 联合一致性
Stage 2各组 TB←C 的分散程度、留出样本误差发现单组偶然误差、板不静止等
EEF Pose 投影FK → Wrist / Cam1 / Cam2 的像素位置与 XYZ 旋转轴叠加排查手眼偏移、相机坐标系方向、相机外参或 FK 定义错误；定量需真实特征点标注
真实应用同一物体或板角点在多个视角转换到 Base 的 3D 位置差比仅看像素重投影更接近实际操作要求

常见问题：误差较大

  • 打印尺寸与配置格长不一致；标定板不够平整。
  • 内参与真实图像分辨率、缩放或去畸变状态不匹配。
  • 把 TCP / flange / tool0 混为同一坐标系。
  • Stage 1 标定板意外移动，或 EEF 旋转变化不足。
  • Stage 2 拍摄时板或机器人还在移动。
  • 混淆 ROS camera_link 与 OpenCV optical frame。

工程注意事项

  • 单次标定不能凭内部误差证明绝对三维精度。
  • 深度噪声、RGB–Depth 对齐和 FK 误差会传递到最终 3D。
  • 更改 Wrist 安装需重做 Stage 1 并重算 Stage 2。
  • 某台固定相机被移动，只需重做对应 Stage 2。
  • 更新 RGB 内参后应重新估计外参 PnP 观测。
  • Stage 2 精度受 Stage 1 手眼外参误差影响。
